---

## 1. Problem

People take home loans without a full side-by-side picture. Aggregators tease rates, gate on phone/PAN, and push leads. Shroffin must show **every bank’s rules in one place**, let the customer **pick**, then **apply once** — no fees, no commission bias.

## 2. Goal (ship)

A customer can: enter a few facts → see matching banks in a comparable table → sort / use static filters → select multiple banks → verify with Google → we receive the application packet → they see a success confirmation. All matching runs **in the browser** on published JSON.

**Non-goals (now):** customer login/profile/application tracking; faceted search (design for it, ship later); live bank APIs; guaranteeing sanction or “best rate.”

## 3. Who / success

| | |
|---|---|
| **Who** | Salaried & self-employed home-loan seekers (Pune first; India) |
| **Job** | “Show me how banks differ for *my* case, then apply to the ones I choose.” |
| **Success** | Table usable on phone; apply packet lands in Firebase with inputs + selected banks + data version; publish never skips human approve |

## 4. Customer flow

1. **Inputs** — loan amount, tenure, purpose (new / BT), occupation, city/project (APF), CIBIL band (optional), women / green flags as data allows  
2. **Match** — client rules engine filters Offers (+ related charges/APF) locally  
3. **Compare** — essentials columns first; sort per column; static filters; open bank detail drawer for full rules  
4. **Pick** — multi-select banks (checkbox)  
5. **Apply once** — disclaimer → Google auth (prove real person) → save packet to Firebase → success popup on return (user need not know backend detail; they see “application received” + next-step copy)  
6. **Ops** — team follows up manually (high-touch today); competition round stays offline for now  

Standing disclaimer: comparison platform, not a lender; figures indicative; bank decides final terms.

## 5. UI / UX (incl. mobile)

| Surface | Behaviour |
|---|---|
| **Desktop** | Sticky bank + select; grouped columns; essentials / all-details toggle; sort on headers |
| **Phone / tablet** | Same data; **3–5 decision columns** default; sticky bank + select; horizontal swipe + edge fade; optional paddles; detail = bottom sheet; fixed “N selected · Apply once” bar |
| **Not** | Dumping all ~72 Offer fields as columns on a phone |

Presentation map (UI groups) separate from raw Excel columns: Rate · Fees · Eligibility · Prepayment · Other.

## 6. Data layers

| Layer | Meaning | Use |
|---|---|---|
| **Primary** | Current public JSON (from Excel via script) | Website table |
| **Secondary** | Archived former primary on each publish | Rate/fee/APF history → future analytics |
| **Tertiary** | Anonymized sanction outcomes (later) | Outcome analytics — no personal identity |

Every live package has a **version ID**. Apply packets store that ID + inputs + selection snapshot.

## 7. System (how it runs)

| Piece | Decision |
|---|---|
| **Source of truth (edit)** | Machine-readable Excel / sheet |
| **Publish artifact** | JSON (+ rules/presentation map) generated by script |
| **Match** | Client-side JSON rules engine — no hosted query DB for v1 |
| **Convert** | One script; change only when a *new data type* appears |
| **Apply store** | Firebase; Google auth for verification; **no** profile/UMS yet |
| **Site** | Static site; primary JSON on CDN/hosting after approve |

### Publish gate (automate work, human authority)

Edit → script convert → auto-validate → diff vs live → **preview** → **human Approve** → promote primary → archive previous as secondary → audit (who / when / version). Nothing public without Approve.

## 8. Scope cut

| In v1 | Later |
|---|---|
| Offers match + essentials table + detail drawer | Faceted search |
| Static filters + column sort | Customer profile / track application |
| Multi-select + Google auth + Firebase packet + success UI | Tertiary sanction analytics productized on site |
| APF-aware project signal where inputs allow | Full self-serve bank competition round |
| Secondary archive on publish | Rich public “rate history” charts |
